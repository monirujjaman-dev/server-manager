# ADR 0006: PostgreSQL for state and VictoriaMetrics for time series

Status: Accepted · Date: 2026-11-19

## Context

The control plane stores relational, transactional data (users, RBAC, servers, jobs, audit log) and high-volume time series (CPU, memory, disk, network, containers).

## Decision

Use **PostgreSQL** (pgx, sqlc, goose) for state and the audit log, and single-node **VictoriaMetrics** (Prometheus remote-write) for metrics.

## Consequences

- Transactional, append-only audit log enforced by database triggers.
- Type-safe queries generated by sqlc; no ORM.
- VictoriaMetrics is far cheaper in RAM and disk than Prometheus or TimescaleDB for this workload and speaks PromQL, so Grafana works if wanted.
- Two data stores to back up and operate.
